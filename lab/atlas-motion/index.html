Accessible sequence

What EvidenceChain shows.

This textual sequence remains available without JavaScript and keeps every lifecycle boundary explicit.

  1. Opening statement. Reviewed evidence vocabulary is ordered, not inferred: every stage needs its own proof.
  2. SOURCE. A named change identity exists as repository source.
  3. CHECKED. Repository-native validation or required checks ran against that exact head.
  4. MERGED. The exact head is integrated on the target default branch.
  5. DEPLOYMENT OBSERVED. A named deployment event was seen for a stated identity.
  6. DEPLOYED. The expected identity is the deployed identity.
  7. RUNTIME VERIFIED. The deployed subject answered a stated runtime check for the expected identity.
  8. LIVE VERIFIED. An independent live check of the public or operator-facing behaviour succeeded.
  9. Order is not proof. A rendered stage never proves the next stage. CHECKED does not imply MERGED; MERGED does not imply DEPLOYED; DEPLOYED does not imply RUNTIME VERIFIED; RUNTIME VERIFIED does not imply LIVE VERIFIED.
  10. Terminal semantics. CLOSED / NOT SHIPPED, FAILED, UNKNOWN / NOT OBSERVED, and NOT APPLICABLE remain separate outcomes.

Input identity: evidence-chain-v0. It is historical reviewed vocabulary from accepted Atlas Infra ADR-0013/ADR-0014 input, rendered offline with no provider, runtime, network, or current rollout claim.

  • Current provider state or production correctness.

  • Any real Atlas change-impact analysis for TwinImpact.
