Building Signal Garden as a Real-Time Browser DSP Instrument

Signal Garden — Browser Audio and Generative DSP // Case Study

The July 2026 Signal Garden rebuild began with a technically correct granular synthesiser whose low-frequency source collapsed into indistinct rumble. The captured version became a bounded browser instrument with seven procedural layers, deterministic evolution, and separate automated and listening-based validation.

Overview

I built Signal Garden to test whether a browser page could behave like a real generative instrument rather than a visual demo with audio attached. The operating constraint was strict from the beginning: synthesis, grain scheduling, filtering, feedback, metering, and per-grain motion had to execute inside an AudioWorkletProcessor. The main thread could describe intent and draw the interface, but it could not own the sample-by-sample signal path.

That boundary worked earlier than the instrument did. The first implementation produced finite stereo audio, moved particles across a canvas, accepted parameter changes, and remained inside its output ceiling. It was technically correct and musically weak. Most of the audible material sat in the low end, so laptop speakers and phone playback reduced the result to an indistinct rumble. Raising the level made the rumble louder without making it clearer.

The failure changed the project. I stopped treating Signal Garden as a granular synthesis exercise and started treating it as a long-form composition system. The revised design draws on the logic of generative ambient work associated with Brian Eno: define a bounded set of interacting rules, give those rules enough musical material to recombine, then allow the system to develop without replaying a fixed timeline. The result still supports direct performance, but it does not depend on constant input to remain alive.

The July 2026 build ran publicly on the Signal Garden page. The captured instrument used a seven-layer procedural source, six ecosystem profiles, a fixed grain pool, adaptive voice budgeting, optional spectral processing, a modulated feedback network, deterministic lifecycle evolution, local audio replacement, browser-native recording, and a particle field derived from the actual grain state.

Design Intent

The page prioritised musical use while keeping its DSP controls inspectable.

System Architecture

Signal Garden is split across two execution domains. The audio thread owns anything that must remain sample-accurate or allocation-bounded. The main thread owns browser capabilities, interface state, file decoding, recording, and low-rate control messages.

ComponentExecution domainResponsibility
SignalGardenProcessorV2AudioWorklet threadSource synthesis, grain creation, filtering, spectral processing, feedback, lifecycle evolution, metering
signal-v2.js controllerMain threadAudio graph creation, ecosystem selection, parameter changes, pointer gestures, file decoding, recording
Canvas rendererMain threadVisualises active grains from transferred active, pan, ratio, and phase values
Web Audio output graphBrowser audio graphMakeup gain, safety compression, user master level, speakers and recording destination

The worklet exposes 12 k-rate parameters: density, grainSize, spread, tone, tension, texture, width, feedback, evolution, quantize, lushness, and shape. Parameter automation remains at control rate because none of these values needs a fresh array for every sample. Seed changes, ecosystem profiles, lifecycle mode, pointer attraction, feedback weather, spectral mode, adaptive quality, and local source changes travel as explicit port messages.

The procedural source writes continuously into an eight-second circular Float32Array. Grains read from that memory at independent positions and rates. This separates the material generator from the granular renderer: one system decides what information enters memory, while another decides how fragments of that information move through pitch, time, stereo space, and envelope shape.

The complete signal path is:

seven procedural source layers
  -> 8-second circular source memory
  -> fixed 48-grain pool
  -> state-variable tone filter
  -> optional 256-point spectral veil
  -> four-line modulated feedback network
  -> DC blocker and worklet soft clipping
  -> 1.75x makeup gain
  -> -7 dB / 20:1 safety compressor
  -> user master gain
  -> browser output and recording destination
Audio-Thread Ownership

Pointer motion may change density pressure, pitch gravity, stereo attraction, and dispersion, but it never moves grain DSP onto the main thread. The interface sends a bounded control message; the processor performs the per-sample work.

Phase I — The Low-Frequency Rumble

Phase IThe Low-Frequency Rumble

The original source memory used three low oscillators plus noise. That was enough to prove scheduling, envelopes, feedback, and stereo rendering, but it was poor material for a finished granular instrument. Most grains sampled related low-frequency waveforms, so changes in density and duration produced new textures without creating new spectral information.

The problem became obvious outside the development setup. On headphones the low field was present, but on laptop speakers and a phone it became difficult to hear. Increasing gain exposed more signal, yet the result still behaved like a single mass. Shorter grains made it rougher. Wider pitch dispersion made it less stable. More feedback made it larger. None of those changes gave the listener distinct events, resonances, or harmonic movement to follow.

Granular synthesis can redistribute time and pitch, but it cannot manufacture detail that does not exist in the source. A grain engine reading a narrow low-frequency buffer is effectively excavating the same small patch of ground from different angles.

Root Cause

The circular source memory contained too little harmonic and temporal information. Output gain was a separate problem; making the signal louder could not give the grain engine material that had never been written into the buffer.

I changed the diagnostic question from “why is this quiet?” to “what information is available for the grains to redistribute?” That reframed the fix around source design rather than another layer of controls.

Resolution

I replaced the three-oscillator source with seven interacting procedural layers, then rebuilt each ecosystem around a different balance of harmonic, modal, transient, noisy, and spatial behaviour.

Procedural Source and Ecosystems

The revised source generator writes seven layers into the same circular memory. Each layer solves a different part of the original information deficit.

LayerImplementationMusical role
Harmonic partialsSeven oscillators driven by ecosystem ratios and a slowly slewed rootStable pitch identity and changing upper structure
Modal resonatorsSix second-order resonators excited by events and noiseBell, body, formant, and decaying acoustic behaviour
Sparse eventsFive event types with short impulses and longer swellsTemporal landmarks that stop the texture becoming continuous fog
Filtered noiseLow-pass and brown-noise componentsSurface texture and resonator excitation
FM colourCarrier and modulator tied to the current harmonic rootControlled inharmonic movement on the experimental side
SubharmonicsRoot at half frequency plus a lower componentWeight without making the entire source a bass drone

The harmonic bank begins from a 55Hz centre and uses seven ratios. A separate target root slews slowly enough to avoid discontinuities when the lifecycle changes harmonic centre. Six modal resonators use profile-specific ratios and decay times; their coefficients are recalculated when the selected ecosystem changes. Sparse events choose between pitched droplets, lower impacts, longer noisy swells, impulses, and metallic combinations. Event lengths range from short transients to several-second gestures, and the Character control changes both their strength and frequency range.

The source is bounded before it reaches the grain engine. The combined layer value passes through Math.tanh, which keeps sudden event and resonance combinations from writing unbounded values into memory. The source buffer is not the final output, so this is not used as a mastering stage. It is a guard around the material that later grain voices will sample repeatedly.

Six ecosystem profiles define the higher-level musical identity:

EcosystemHarmonic fieldDefining behaviour
Glass RainPentatonic-weighted ratiosBright resonant droplets, high air content, widening stereo movement
Tidal MemorySuspended fifth relationshipsLong grains, lower event rate, reverse-feeling swells, broad feedback memory
Lichen ChoirJust-ratio clusterSlow beating, formant-like resonance, restrained transients
ChoralConsonant formant fieldHarmonic and modal emphasis that suggests voices without synthesising speech
Deep DroneSubharmonic fifthsDeliberate low weight balanced by sparse higher events
Anxious SwarmUnstable tritone clusterShort grains, high tension, FM colour, rapid migration, denser events

An ecosystem is not a preset that replaces the engine. It supplies weighted pitch ratios, modal ratios, layer gains, event rate, motion genetics, and starting parameter values. Genome A and Genome B can be blended and mutated deterministically. quantize controls attraction to the weighted pitch field, while tension dissolves that gravity into continuous and microtonal movement. Those controls have different meanings; keeping them separate avoids using “randomness” as a single vague parameter.

Visitor audio uses the same grain path. The browser decodes a selected file locally, downmixes all channels to mono, caps the material at 120 seconds, and transfers one Float32Array into the worklet. There is no upload endpoint and no server storage. Restoring the procedural source clears the external buffer and returns the same bounded grain objects to the generated memory.

Source Before Control

The largest improvement came from increasing the quality of information entering the granular system. Extra knobs became useful only after the source could produce contrast worth controlling.

Phase II — Silent Startup and Gain Staging

Phase IISilent Startup and Gain Staging

The multi-layer source improved the eventual sound, but startup remained misleadingly quiet. The source buffer is eight seconds long and begins filled with zeros. Early grains were allowed to choose positions across unwritten regions, so a large proportion of the first render window sampled silence even while the source generator was working correctly.

This looked like an output-level failure because the signal became stronger over time. Raising the final gain reduced the apparent delay, but it also reduced headroom once the buffer filled and feedback states became active.

Root Cause

Procedural grains selected delay positions from the full circular buffer before the source generator had written that much material. The gain stage was compensating for grains reading zeros, not for a consistently quiet synthesiser.

The grain spawn path now derives its maximum delay from sampleCounter. During startup, a procedural grain can only read material that has already been written. A minimum delay of 20ms keeps the read head behind the writer without exposing unused memory. Once the buffer has filled, the same calculation expands naturally to the full eight-second history.

I then separated audibility from safety. The worklet retains its own soft-clipped ceiling at approximately 0.72. Outside the worklet, a 1.75x makeup stage restores useful level. A DynamicsCompressorNode follows with a -7 dB threshold, zero knee, 20:1 ratio, 3ms attack, and 240ms release. The user master gain sits last and starts at 50 percent.

That order matters. Feedback-heavy states encounter the safety compressor before the listener raises the master level. Recording branches from the final master, so the captured output matches what the browser sends to the destination rather than bypassing the safety path.

Resolution

Grain reads were restricted to written source history, then audibility and safety were split into explicit makeup, compression, and user-volume stages. Startup became immediate without sacrificing the feedback ceiling.

Listening Level

The output path is bounded, but bounded is not the same as quiet on every device. Signal Garden starts at 50 percent and leaves the final listening level under user control.

Bounded Grain and Feedback Engine

Signal Garden allocates all 48 grain objects during processor construction. There is no new Grain() inside normal render operation. A grain moves from grainPool into the active array when spawned, then returns to the pool when its envelope completes. The invariant is simple and testable:

active grains + pooled grains = 48

Each grain stores age, duration, source position, starting ratio, starting and ending pan, pitch drift, orbit phase, orbit rate, gain, source-rate ratio, and the current values required by the visualisation. Grain length is derived from grainSize and density pressure. Pitch begins as a blend of raw dispersion and a weighted ecosystem ratio, then tension introduces microtonal deviation. Envelope shape morphs from percussive decay through a Hann-like smooth window toward a reverse shape.

Stereo rendering uses equal-power panning. Pan moves between a start and end value while a slow orbit adds local motion. Pitch can drift across the grain lifetime. When the pointer attractor is active, horizontal position pulls pan, vertical position pulls pitch ratio, and pointer velocity increases strength and density pressure. The canvas therefore displays and manipulates actual DSP state; it is not an animation responding to an unrelated analyser node.

The voice budget adapts without changing the object pool. If measured render load stays above 0.78, the active limit falls by four voices at a time until it reaches 24. If load stays below 0.45, it rises by two until it returns to 48. The decision runs every 64 render quanta rather than oscillating on every block. Browsers that expose a usable high-resolution timer receive measured load; the fallback estimate combines grain pressure and the cost of enabling spectral processing.

After the grain mix, a state-variable filter combines low and band outputs. tone moves the cutoff from roughly 220Hz toward 11kHz; tension changes the resonant balance. The optional spectral stage uses a 256-point FFT with a 128-sample hop:

  • Freeze captures magnitudes while current phase continues to move;
  • Blur exponentially accumulates magnitudes into a persistent spectral memory;
  • Shimmer remaps energy upward by reading lower source bins.

The spectral result feeds a four-line feedback network. Delay lengths of 1493, 1601, 1747, and 1867 samples are scaled for the active sample rate. Four independent low-frequency modulators move the read positions. A Hadamard-like sign pattern redistributes energy between lines, while feedback is clamped to 0.82 after the selected weather profile applies its scale.

Clear, Mist, Bloom, Storm, and Void change modulation depth, modulation rate, wet level, and feedback scaling. They do not bypass the feedback ceiling. This keeps Weather as a musical macro rather than a hidden route around the safety design.

Bounded Expressivity

The interface can push the system toward dense grains, long feedback, spectral freezing, rapid pointer movement, and experimental event rates. Every one of those gestures still operates inside fixed object ownership and explicit feedback limits.

Phase III — Shared Memory Without Isolation

Phase IIIShared Memory Without Isolation

The first playable particle field used SharedArrayBuffer to expose grain state to the canvas. The data layout was small, but the browser capability came with a large deployment consequence: shared memory requires cross-origin isolation headers. A visualisation path had become a prerequisite for starting the audio system.

That dependency was disproportionate to the problem. The main thread did not need to mutate live worklet memory. It needed an occasional snapshot of 48 grains, each represented by four values: active state, pan, ratio, and envelope phase.

Root Cause

The transport selected shared-memory semantics for a one-directional, low-rate snapshot. A non-essential display feature forced the entire page to satisfy a stronger browser security mode than the DSP required.

The replacement uses two reusable Float32Array buffers. Each buffer holds 48 × 4, or 192, float values. The main thread primes the worklet with both buffers. At approximately 60Hz, the processor takes one available buffer, fills it, transfers its backing memory to the main thread, and continues rendering. After drawing, the main thread transfers that same buffer back for reuse.

No grain object crosses the thread boundary. No visual payload is allocated per animation frame. If both buffers are temporarily in flight, the worklet skips a visual update rather than blocking audio or allocating a third buffer. Sample-accurate motion remains private to the processor; the canvas receives a bounded representation suitable for human perception.

Resolution

A two-buffer transfer loop removed the cross-origin isolation dependency, retained allocation discipline, and made visual back-pressure harmless to the audio thread.

Deterministic Long-Form Evolution

A better source and grain engine solved the immediate sound problem, but an interesting 10-second texture is not automatically an interesting 10-minute instrument. I needed structure above individual grains without writing a fixed arrangement.

The processor uses separate deterministic random streams for grain behaviour, lifecycle evolution, and sparse events. All three derive from the same seed but use different initial states, so changing event timing does not automatically rewrite every grain trajectory. Reseeding returns active grains to the pool, resets the lifecycle, resets modulation phases, and reproduces the same starting conditions.

Four sinusoidal timescales influence different parts of the system:

TimescaleFrequencyApproximate periodResponsibility
Micro0.083Hz12sGrain-level variation and transient-layer movement
Phrase0.021Hz48sDensity, noise, harmonic drift, and event balance
Ecosystem0.0043Hz233sModal activity, sub balance, envelope shape, and lushness
Epoch0.0011Hz909sFM colour, feedback movement, and very slow structural change

Autonomous mode also moves through seven named lifecycle states. Each profile contains density, brightness, event rate, resonance, motion text, and seven layer multipliers.

StateStructural role
DormantHolds energy in long grains and low event density
GerminationIntroduces fresh excitation and partial activity
BloomOpens the harmonic field and stereo image
MigrationMoves pitch centres and grain trajectories
StormRaises event probability, noise, FM colour, and turbulence
DecayReduces density while feedback and resonators reveal memory
RegenerationRebuilds source material for the next cycle

At an ambient Character setting, a lifecycle lasts approximately 20 to 62 seconds. At the experimental edge, the range contracts toward nine to 31 seconds, with a hard minimum of six seconds. State selection moves to the next lifecycle 76 percent of the time, skips ahead 16 percent of the time, and chooses a random state for the remaining eight percent. Migration and Regeneration may shift the 55Hz harmonic centre by -5, -2, 0, 2, 5, or 7 semitones.

Character does not swap to a second engine. It biases the same system. Moving toward experimental increases FM, transient, and noise weighting; raises event rate and possible event frequency; shortens lifecycle durations; and adds harmonic tension. The instrument keeps its identity while its behaviour becomes less stable.

Perform mode suppresses most autonomous lifecycle influence without freezing the engine. The current lifecycle stops advancing, direct macro and pointer controls dominate, and slow evolution remains at a reduced scale. This creates a performance mode rather than an “off” state for generative behaviour.

Deterministic Does Not Mean Repetitive

Determinism gives the system a reproducible path from a seed and topology. Long periods, weighted state transitions, mutation, cross-pollination, and direct gestures still produce variation without hiding the result behind uncontrolled randomness.

Performance Interface and Local Tools

The development interface originally exposed genome selectors, mutation, macro controls, weather, spectral modes, local source handling, recording, 12 detailed parameters, and telemetry at the same time. That was useful while debugging. It was a poor first encounter because every control appeared equally important.

The default performance surface now contains:

  • Start and Stop;
  • master volume;
  • Autonomous or Perform mode;
  • ecosystem selection;
  • Character;
  • the interactive grain garden.

Three disclosure panels hold the deeper layers: Shape the Ecosystem, Source and Capture, and Advanced DSP. The lifecycle panel explains the current state in plain language and shows the active source layers. Stage labels expose the lifecycle, harmonic field, and motion description. Engineers can still inspect render load, active grains, voice limit, over-budget blocks, source mode, spectral mode, and feedback weather.

The particle field is both visualisation and control surface. Pointer X maps toward stereo gravity. Pointer Y maps toward pitch gravity. Velocity determines attractor strength and adds dispersion pressure. Messages are coalesced through requestAnimationFrame, so high-frequency pointer events do not become an unbounded stream into the worklet.

The browser can record the final master stream with MediaRecorder. MIME selection prefers Opus in WebM, then Opus in Ogg, then plain WebM according to browser support. Chunks are collected every 500ms and assembled into a local object URL when recording stops. Nothing is uploaded.

Shareable state and local audio support preserve the same privacy boundary. Ecosystem, seed, blend, mutation, macro position, weather, and spectral choices can be encoded into a deterministic state. Audio files stay inside the browser and are transferred directly to the worklet after decoding.

Result

The same page now supports three levels of use: listen to an autonomous ecology, perform through musical macro controls, or open the engineering drawers and inspect the processor in detail.

Validation

The implementation baseline is PR #33, building on the transport and interaction work introduced earlier. The automated harness executes the real worklet source inside a Node vm context with a mocked AudioWorkletProcessor port. It does not reimplement the DSP as a separate mathematical model.

The main render test processes 1,500 quanta of 128 samples at 48kHz, which covers 192,000 stereo frames. For every sample it checks finite output. For every quantum it checks the voice limit and the fixed grain ownership invariant. Across the complete run it requires:

  • RMS above 0.003;
  • peak output above 0.02;
  • peak output at or below the expected 0.721 worklet ceiling;
  • active voice limit between 24 and 48;
  • active and pooled grains summing to 48.

Additional tests force a lifecycle transition and verify explanatory telemetry, confirm that Perform mode prevents lifecycle takeover, render 8192 procedural samples and check that multiple source layers become active, replace the source with a local Float32Array, restore procedural mode, and inspect the HTML and controller for the 50 percent volume default, 1.75x makeup gain, compressor, and user master stage. The suite also asserts that the processor contains no SharedArrayBuffer reference.

The exact harness remains in signal-garden-v2.test.mjs. These tests establish numerical safety, bounded ownership, transport shape, and state-machine behaviour. They do not establish musical quality or prove performance across every browser implementation.

I separately tested the deployed page using Firefox, Chrome, and DuckDuckGo Browser across a macOS laptop, a Windows laptop, and an Android phone. The browser list and device list are intentionally independent; I did not test every browser on every device. Mobile audio started correctly after user interaction, the touch surface remained usable, and the richer source retained audible detail outside the development listening setup.

The most important manual result was not that the page made sound. It was that Glass Rain, Tidal Memory, Lichen Choir, Choral, Deep Drone, and Anxious Swarm no longer collapsed into the same low-frequency identity. That judgment remains subjective, so I report the devices and method rather than converting it into a false perceptual score.

Validation Boundary

The automated suite covers a short deterministic render window and the manual checks cover selected browsers and devices. I have not completed a formal perceptual study, a full browser-device matrix, or a long-session CPU benchmark on low-end mobile hardware.

Outcomes

Audio architecture
Eight-second source memory, fixed 48-grain pool, adaptive 24-to-48 voice limit, and bounded feedback path
Source design
Seven interacting synthesis layers and six ecosystem profiles replaced the indistinct low-frequency drone
Long-form behaviour
Four deterministic timescales and seven lifecycle states develop the instrument without a fixed arrangement
Browser validation
Audio and touch interaction worked across selected desktop browsers, macOS, Windows, and Android

Signal Garden is now a public browser instrument rather than a granular demonstration. The finished system separates source composition, granular redistribution, spectral colour, feedback memory, lifecycle structure, interface intent, and final gain control. Each boundary has its own failure mode and its own validation method, which makes the instrument easier to reason about than one large block of generative code.

The broader principle is that technical correctness and perceptual success are different engineering targets. Automated tests can prove finite output, bounded allocation, deterministic state, and explicit safety limits; only listening can reveal that the material itself is too weak. The useful response is not to distrust testing, but to give each kind of evidence authority over the question it can actually answer.
